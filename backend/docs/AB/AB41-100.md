# [AB-66] Fix Order Schema Property Mapping in Email Dispatch Utility

## Change Summary

- **Module**: Backend (`src/core/utils/orderDelivery.js`)
- **Impact**: Order Email Dispatch (`sendOrderEmailsAsynchronously`) — Root Cause Bug Fix
- **Description**: Identified property name mismatch between MongoDB `OrderModel` schema, Frontend checkout payload (`useAppStore.js`), and `orderDelivery.js`:
  1. `orderDelivery.js` extracted `customerName` from `order.customer.name` instead of `order.customer.fullName` (as stored in Mongo schema), causing `customerName` to resolve as `undefined`.
  2. `orderDelivery.js` checked `order.billingAddress` (which is not stored as a top-level field in `OrderModel`), ignoring `order.customer.address`, `city`, `thana`, `district`, `zip`, causing address to resolve as an empty object.
  3. `orderDelivery.js` checked `item.variant` instead of joining `item.size` and `item.concentration` stored by `OrderModel`.
  These `undefined` values caused email templates to fall back to hardcoded developer test data. Updated `orderDelivery.js` to correctly extract `order.customer.fullName`, construct address from Mongo customer fields, and join `item.size` & `item.concentration`.

## Affected Files

- `backend/src/core/utils/orderDelivery.js` — Corrected data extraction properties
